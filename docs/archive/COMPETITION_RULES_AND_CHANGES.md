## 1. 대회 규칙 (현재 코드에 인코딩된 상태)

1:1 건 전용 도그파이트, F-16, **200초**.

### 1.1 데미지 — 시간 3단계 (가장 중요)

데미지는 고정 원뿔이 **아니다.** 시계가 갈수록 원뿔이 넓어지고 계수는 떨어진다.
정의: `src/dogfight/config.py:77-87` (`wez_phases`)

| phase | 시각 | LOS(반각) | 거리 | 계수 |
|---|---|---|---|---|
| 1 | 0~100 s | < 1° | 500~3000 ft (152.4~914.4 m) | ×1.0 |
| 2 | 100~150 s | < 2° | 500~3500 ft (152.4~1066.8 m) | ×0.3 |
| 3 | 150~200 s | < 3° | 500~4000 ft (152.4~1219.2 m) | ×0.1 |

**주의 1 — 전각/반각.** 설정의 `angle_deg`는 **전각**이다(2.0 / 4.0 / 6.0). 판정은
`angle_deg / 2 >= |ATA|` (`src/dogfight/envs/single_agent_env.py:1289`)이므로 실제 반각은
1° / 2° / 3°. 브리핑의 "LOS < 1도"와 일치한다.

**주의 2 — 좁은 원뿔이 항상 이긴다.** phase가 열린다고 이전 phase가 닫히는 게 아니다.
t=170 s에도 1° 안에 있으면 계수 1.0을 받는다. 그래서 판정 루프는 **좁은 순으로 정렬해
첫 매치에서 반환**해야 한다 (`single_agent_env.py:1279-1292`). 순서를 바꾸면 조용히 계수가
1.0에서 0.1로 떨어진다.

**프레임당 데미지 공식** (`single_agent_env.py:1290`):

```
damage = (max_range - distance) / (max_range - min_range) * coefficient * delta_t
```

즉 **가까울수록 크다.** 최대거리에서 0, 최소거리에서 최대. 매 프레임 누적된다.

### 1.2 추락

`min_altitude = 1000 ft = 304.8 m` (`src/dogfight/config.py:17`).
이 아래로 내려가면 에피소드 종료. 대회에서는 곧 패배다.

### 1.3 종료 조건

- HP 소진 → 승/패
- 고도 하한 이탈 / FDM 실패 → 추락
- 200초 경과 → 타임아웃, 데미지·HP 우세로 판정

## 2. 변경 이력

### 2.1 물리 괴리 해소 (2026-07-31) — **해결됨**

**증상.** 학습 시뮬과 BattleViewer가 서로 다른 비행기를 날렸다. 학습한 정책이 뷰어에서
전이되지 않는 근본 원인이었다.

**경과.** 주최측이 BattleViewer **V1.0**에서 비행모델을 `JSBSimAIPLib` 플러그인으로 교체했다:
`DogFightViewer/Plugins/JSBSimAIP/ThirdParty/JSBSimAIPLib/Win64/`.
구 `NeoJSBSim.dll`과 `Binaries/Win64/` 밑의 v0.3 기체 데이터는 아직 남아 있지만 **비행을
구동하지 않는다.** 그 경로로 비교하면 잘못된 결론이 나온다.

**남아 있던 마지막 차이 = 연료 하나.** 엔진 교체 후 `aircraft/f16/f16.xml`에서 유일하게
다른 것은 탱크 2개의 `<contents unit="LBS">`였다. 학습 릴리스 1500, 뷰어 3486
(기체 질량 약 1800 kg 차이).

4572 m / 200 m/s에서 고정 입력 34초 프로브(피치 −46°, 속도 200→393 m/s 급강하 포함) 측정:

| plz 연료 | 고도 RMS | 속도 RMS | 피치 RMS |
|---|---|---|---|
| 1500 lb (수정 전) | 최대 **104.8 m** | 6.8 m/s | 1.00° |
| 3486 lb (뷰어와 동일) | 최대 **0.50 m** | 0.03 m/s | 0.006° |

34초 시점 대조: 뷰어 고도 826.7 m / 학습 826.2 m, 피치 −46.26° / −46.27°.

**조치.** 뷰어 플러그인의 `f16.xml`을 그대로 복사. 현재 sha256 `909cfe0e…`로 뷰어와 바이트 동일.
백업 `aircraft/f16/f16.xml.pre_v10_fuel_bak`.

**교훈.** 이건 엔진 적분 문제가 **아니라 기체 질량** 문제였다. NeoJSBSim 역공학에 며칠을 썼는데
원인이 아닌 쪽이었다. 앞으로 "전이가 안 된다"를 정책 탓으로 돌리기 전에 **반드시 축 분리
프로브를 먼저 돌릴 것.**

**재검증 절차** (뷰어 새 빌드마다):
1. 위 플러그인 경로의 `aircraft/`, `engine/`, `scripts/`를 plz와 diff.
   `f16_init.xml`이 다른 건 **정상** — FighterSim이 매 에피소드 덮어쓰는 임시 파일이다.
2. `scratch_viewer_probe_axes.py`를 blue로 붙여 경기 1판 → `probe_axes.csv`.
   (주최측이 물어봤던 `0,0,0,0` / `0,0.05,0,0` 케이스가 앞 두 구간이다)
3. plz 루트에서 `python scratch_local_axes_compare.py`.

### 2.2 규칙 수정 — 시간 3단계 데미지 & 추락 고도

릴리스 기본 설정은 데미지를 **고정 원뿔**로, 추락 고도를 **300 m**로 적어놨었다. 둘 다 틀렸다.

- `config.py`: `min_altitude` 300.0 → `1000 * FEET_TO_METER` (304.8)
- `config.py`: `wez_phases` 신설 (위 1.1 표)
- `single_agent_env.py`: `_active_wez_phases()` / `_active_wez_for_observation()` 추가,
  `update_damage()`를 "좁은 phase 우선, 첫 매치 반환"으로 재작성
- `single_agent_env.py`: 관측에 넘기는 사본의 `SIM_TIME`을 **경과 초**로 재작성
- `unreal/policies.py`: 뷰어 클라이언트도 `SIM_TIME = frame_index / 60.0`으로 채운다
  → 학습과 배포에서 같은 양이 된다 (이게 어긋나면 phase 판단이 통째로 틀어진다)

관측 모듈 `student/team01_phase_observation.py` (35채널 = tactical32 + 3):
`time_remaining`, `phase_half_angle`, `phase_max_range`. phase 표는 `dogfight.config`에서
import하므로 학습·배포·데미지 계산이 갈라질 수 없다.

### 2.3 추락이 공짜였던 버그 (2026-07-31) — **수정됨**

**증상.** `crash_rate`가 **전 iteration 1.00**. 그리고 학습이 진행될수록 `ep_len_mean`이
**줄었다** (1739 → 780 → 671).

**원인.** `reward.py`에서 승/패가 아닌 종료는 전부 `draw_reward`로 떨어지는데 S1 설정이 그걸
`0.0`으로 뒀다. 즉 땅에 박아도 **페널티 0**. 반면 에피소드 누적 보상은 음수였다
(step penalty + `range_progress` 약 −80). 따라서 **최대한 빨리 죽는 것이 최적 정책**이었고,
SAC는 정확히 그걸 찾아냈다.

**조치.** `reward.py`의 terminal 분기에 추락 케이스를 명시적으로 추가하고
`crash_reward` / `crash_altitude_m` 설정 키를 신설. S1에서 `-100.0` / `350.0`
(`min_altitude` 304.8 m보다 살짝 위 — 종료 시점 오버슛을 포함시키려고).
3-iteration 스모크로 `ep_reward_terminal = -100.0` 실제 적용 확인.

**일반화된 교훈 — 이게 이 문서에서 가장 재사용성 높은 항목이다.**
명시적으로 채점하지 않은 종료 사유는 fallback 값을 물려받는다. **per-step 보상이 음수면
채점 안 된 모든 종료가 양의 가치를 갖는다.** 학습 중 에피소드 길이가 줄거나 어떤 종료율이
1.00에 고정되면, shaping 가중치를 건드리기 전에 `_classify_outcome`의 **모든** 종료 사유가
의도한 숫자로 매핑되는지부터 확인할 것.

### 2.4 수정 경계 (2026-07-31 변경)

**외부 통신 코드를 제외하면 릴리스의 모든 파일을 수정해도 된다.** 구 `CLAUDE.md`의
"절대 금지" 목록(`src/dogfight`, `policies.py`, `aircraft/`, `engine/`, `scripts/`)은 **폐기됐다.**

단 **`battleviewer*` / `BattleServer_*` 는 절대 수정 금지.** 읽기 전용이다. 괴리는 항상
우리 쪽을 뷰어에 맞춰서 없앤다.

## 3. 현재 상태 (2026-08-01 새벽)

록히드 PHANG-MAN 구조: 저수준 전문가들을 얼려두고 selector를 학습. **전문가는 전부 RL**이다
(BT 전문가는 채택하지 않았다 — 과거 하이브리드에서 게이트 전환 0회로 실패했다).

**S1 P1-Shooter** 학습 중. 유리한 기하에서 시작해 "1° 안에 유지하면 데미지가 들어온다"를
먼저 경험시키고, 거기로 가는 법은 불리한 스폰 비중을 늘려 역으로 학습시킨다.
에피소드는 **항상 200초** — 짧게 하면 관측의 `time_remaining` / phase 채널이 실전에 없는
분포로만 학습돼 정책이 붕괴한다(과거 실증).

병렬 2개, 딱 한 변수만 다르다:

| run | 실험 | 변수 |
|---|---|---|
| A_ctrl | `team01_s1_p1_shooter` | `front_hold_scale: 0.20` |
| B_tight | `team01_s1b_tight_shaping` | `front_hold_scale: 0.05` |

가설: 45° 원뿔 보상(`front_hold`)이 후하면 어중간한 조준으로도 충분히 벌어서 1° 창까지 밀
유인이 없다. 실제로 관측된 값이 `front_hold +60.7` / `aim_hold +14.6` / `damage 0.0`이었다.

변형 생성은 `make_variant.py`로 한다 — 승자 YAML에서 **한 스칼라만** 바꿔 뽑고, 부모에 없는
키나 값이 같은 변형은 거부한다(설정이 조용히 무시되는 사고를 막으려고).

### BT의 역할 (합의된 방향)

전문가가 완성되면 **BT는 조종 루프에서 완전히 빠진다.** 남는 역할은 셋:
1. **스파링 파트너** — 다양한 BT DLL로 커리큘럼 구멍을 메운다. 알려진 최대 패인이
   "뷰어 RedFlyBT의 수직 zoom-and-dive를 학습이 한 번도 안 보여줬다"는 것이라,
   수직파 BT 상대가 우선순위가 높다. self-play만으론 이 구멍이 안 메워진다.
2. **배포 보험** — 모델 번들 로딩 실패 시에만 켜진다. 제어 루프 미개입이라 리스크 0.
3. **하드 안전 바닥** — 조건부. **배포에서 BT가 하는 일은 학습에도 똑같이 있어야 한다.**
   배포에만 안전망을 달면 정책이 못 본 힘이 조종간에 개입해 새 train/deploy 괴리가 생긴다.
   현재 권고는 **넣지 말 것** — 고도 하한은 이미 보상에 들어가 있다.

BT가 컷인·포지셔닝·조준·전술 판단을 맡는 구조는 이미 한 번 실패했다. 되살리지 말 것.

## 4. 함정 목록

1. **뷰어 클라이언트 `command_delay_sec`는 0.0이어야 한다.** 기본값 0.06이면 경기가 멈춘다
   (시계는 가는데 비행기가 안 움직임). 하루를 날린 적 있다.
2. **정책 스텝은 0.100초** (60 Hz × action_repeat 6). 0.15초가 아니다.
3. **BT DLL의 `Reset()`을 쓰지 말 것.** 모든 트리를 지워버려서 `Step()`이 초기화 안 된
   `ControlValue`를 반환한다. `RemoveBT` + `CreateBehaviorTree`를 쓸 것.
4. **`los_*_deg` 컬럼을 신뢰하지 말 것.** ATA는 원위치+자세에서 재계산한다.
   forward = (cos p·cos y, cos p·sin y, sin p), +pitch에 +Z.
5. **C++ 변경 시 DLL sha256이 바뀌었는지 확인.** 안 바뀌면 빌드 미반영 — 이 프로젝트 최대 함정.
6. **stdout 버퍼링을 행(hang)으로 오진하지 말 것.** 멀쩡히 돌던 학습을 3번 죽인 적 있다.
   `PYTHONUNBUFFERED=1`을 항상 켠다.
7. **PowerShell로 한글 YAML을 읽지 말 것.** UTF-8을 cp949로 읽어 파일을 깨뜨린다. Python으로 쓴다.
8. **새 실행은 iter 1에서 설정이 먹었는지 먼저 확인한다.** 하룻밤에 두 번 날린 원인이 모두
   iter 1에서 보였을 문제였다(연료, `ep_reward_terminal=0`).

## 5. 미해결

- **`target_entropy` 리포팅 불일치.** YAML은 `-1.0`인데 로그 컬럼은 `-4.0`(= "auto", −dim(A)).
  실제 빌더 경로(`build_algorithm_config` → `SACConfig`)를 직접 호출해 `-1.0`이 끝까지 유지되는
  것은 확인했다. alpha는 0.036 부근에서 평형이고 0.005로 붕괴하지는 않는다. 리포팅 아티팩트로
  **추정**하지만 증명되지 않았다.
- **뷰어 엔진 교체의 최종 확정.** V1.0에서 `JSBSimAIPLib` 플러그인은 확인했으나, 주최측이
  이걸 예선 본 환경으로 확정했는지는 문서로 확인되지 않았다.
